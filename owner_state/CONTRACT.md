# Hash optimization and owner binding experiment

Baseline: repository commit b0d17235d5bc7582066bd3625eee31cb3bab3674 and leanVM-b 8494c5d5df323f2b97ed89272942a4bee6247078. The existing real_state evidence is immutable.

Goal: measure correct compiler/hash improvements to the same state lookup and add the note opening H = Keccak256(owner_addr || secret). The secret is a 32-byte public benchmark fixture, not a real user's secret. The authenticated storage value remains available inside the relation; no authorization is executed. Public statement fields are the selected anchor, note commitment and storage slot, domain-separated and bound through the VM public digest. Address, secret and stored value are witness data. The pinned proof backend does not establish witness hiding; this experiment must not claim owner privacy.

Compare baseline and candidate on the exact same owner relation, public inputs, real state fixture and fixed public encoding shape. Preserve real Keccak-256, SHA-256, all RLP/MPT checks, witness Booleanity and public binding. Do not substitute a friendlier hash or trust host hash hints. ISA and proof constraints remain unchanged. Profiling changes may add timers only, with their exact source patch recorded.

Candidate screening: per-hash common-subexpression elimination, dead-code elimination preserving constraint side effects, and SHA carry variants. Reject word packing as an assumed free win: its range/decomposition costs must be included. Record rejected variants. Choose by actual whole-program counts and padded commitments, then measure, without requiring a particular winner.

Correctness gates: independent native Keccak/SHA references, padding and multi-block tests, full-adder truth tables, differential baseline/candidate statements, input-independent compilation, malicious witnesses executed after generation, live proofs and witness-free verification. Optimizer tests must preserve checks on dead computations and conflicting writes.

Measurements: same instrumented binary and eleven Rayon workers for all variants, sequential fresh processes on recorded AC power. One clearly identified warmup per condition, then eight balanced randomized blocks covering both implementations and all three anchors (48 measured proofs). No measured sample is discarded. Record environmental state before/after each run; a power-source change makes cross-run timing comparisons inconclusive. Primary metric is complete prove time including execution, witness construction and return cleanup; secondary metrics include exclusive phases, execution-only hash microbenchmarks, instruction counts, commitment size, proof bytes, verification and process memory. Timings do not estimate a general machine distribution. Report paired block ratios, all samples and within-batch uncertainty, including ambiguous results.

Hash work inside the state program is attributed by exact emitted/live operation counts. Hash execution wall time is also measured in standalone programs of the actual input lengths, clearly labeled as a separate diagnostic. Do not infer additive per-hash proving time by subtracting full proofs. Do not add nested profiler timings or concurrently executed background setup to wall totals.

Analysis fixed before collection: pair conditions by block and report geometric mean time ratios with 95% Student-t intervals on the eight log ratios (7 degrees of freedom). These intervals assume approximately independent, normally distributed block log ratios; they describe this batch and are exploratory, without adjustment for multiple comparisons. Show every observation, medians for absolute times, and arithmetic means for additive phase stacks. The six-row order cycle is completely balanced; the final two blocks are a partial second cycle. No timing-based stopping or outlier deletion is allowed.
